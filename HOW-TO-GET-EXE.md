# Как получить готовый ORION.exe, чтобы отдать другу

В репозитории лежит `.github/workflows/windows-release.yml`. Он сам поднимает
чистую Windows-машину на серверах GitHub, ставит Qt 6.6 (MSVC), собирает
Release-версию, дособирает рядом с exe все нужные Qt-DLL и рантайм MSVC
(`windeployqt --compiler-runtime`), упаковывает всё в один zip и кладёт его
как скачиваемый артефакт. Собирать самому и ставить Qt не нужно.

## Шаги

1. Залей этот исходник в репозиторий на GitHub (обычный `git init` + `git add .`
   + `git commit` + `git push`, если ещё не в репозитории).
2. Открой вкладку **Actions** в репозитории.
3. Если сборка не запустилась сама (запускается на push в `main`/`master`),
   выбери слева **Windows release build** → **Run workflow** → **Run workflow**.
4. Подожди 5-10 минут, пока значок станет зелёным.
5. Открой этот прогон, внизу страницы будет артефакт **ORION-windows** — это и
   есть zip с `ORION.exe` и всеми DLL рядом. Скачай его — это то, что можно
   целиком скинуть другу (просто разархивировать и запустить `ORION.exe`,
   ничего ставить не надо).

## Если сборка красная (упала)

Открой лог упавшего шага в интерфейсе Actions — там будет видно, на чём
именно споткнулось (обычно это либо версия Qt, либо отсутствующий модуль
Sql). Пришли мне текст ошибки — я не смог прогнать этот workflow сам (в моей
песочнице нет Windows и GitHub Actions), в отличие от C++-фиксов из
diagnostic_engine.cpp, которые я реально собирал и тестировал здесь. Так что
первый прогон стоит считать черновым и поправить по факту, если что-то не
сойдётся с версией Qt на раннере GitHub.
